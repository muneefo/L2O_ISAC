5. Phase D: independent adversarial audit — mandatory first experiment
For every method and held-out scenario, freeze Fa, Fd, and all receive filters. Search only uncertainty errors. Do not allow beamformer updates during attack evaluation.

Respect the paper's separable robust objective:
V(B) = rho * min_delta_h gamma_c(B, delta_h)
       + (1-rho) * min_(delta_t,delta_r) gamma_s(B, delta_t, delta_r).
Search communication and sensing errors with their correct shared variables and domains. Do not evaluate separate per-target minima with inconsistent versions of a shared error. Do not introduce correlation between uncertainty sets that changes the problem.

Create an attacker in a module independent of the learned MinNet update code. Reuse verified physics and projections, but not learned attack schedules. Include:
- Zero and learned-terminal-error candidates.
- Random feasible candidates, including interior and boundary points.
- Multi-start PGD with validation-tuned step sizes, optional backtracking, and several iteration budgets.
- At least one additional search strategy, such as projected Adam or a derivative-free search on tiny cases, if supported and numerically reliable.
- Best-so-far candidate retention, so larger nested candidate budgets cannot worsen the lowest utility found.
Suggested pilot budgets: 5 restarts and 50/200 steps on at least 100 held-out scenarios, reduced only with an explicit resource explanation. Full-study target: 20 restarts and 200/1000 steps on at least 1000 scenarios where feasible, with attack convergence plots. These are starting budgets, not guarantees of attack sufficiency.

For a fixed method/scenario, define an attack-gap diagnostic using the same utility:
gap = utility_at_learned_terminal_errors - lowest_utility_found_independently.
Include the learned-terminal candidate in the independent pool; the gap should then be nonnegative up to numerical tolerance. Compare gamma_c and gamma_s separately as well.

Important interpretation: the lowest feasible candidate utility is an upper bound on the true minimum utility, not a certified lower bound on robust performance. A large attack gap diagnoses weak evaluation; a small gap does not prove global optimality.

Attack every compared method independently. Also evaluate on a shared union of candidates found for all compared methods per scenario. This helps reveal method-specific attacker weaknesses without claiming certification. Keep the frozen test set out of model selection.

Gate D: report whether H1 is supported. If not supported, say so and do not market the extension as fixing an observed failure. H2 requires both graph evidence and experiments, not attack results alone.
