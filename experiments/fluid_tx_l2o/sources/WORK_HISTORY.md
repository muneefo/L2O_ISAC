# Execution corrections and limitations

- Initial pre-training comparison failed at about1.26e-9 in float64 positions because the new schedule initializes its scalar in float32 (then casts), whereas the comparison passed the Python double literal. The comparison now passes the actual schedule to the existing solver; tolerances were not relaxed. The initial tool output exposed this failure; the first local test log was overwritten by the passing rerun. We do not claim a preserved full initial failure log.
- Independent attack results and trained checkpoints were generated before the source runner's union fix. A direct per-scenario check found that the new cross-design shared-pool wrapper compared candidates using their donor beamformers before retaining their errors with recipient beamformers. This could increase a reported minimum. Training and per-method independent attacks were unaffected. The wrapper now calls the existing validated union_attack, which evaluates each candidate on the recipient's frozen design. A regression test verifies component minima and frozen beamformers. All shared-pool scores were rebuilt. Rejected initial aggregate scores are retained in outputs/study/rejected_initial_union_scores.pt and excluded from reports. The changed runner hash is an evaluation-only correction; model.py and the actual training procedure/checkpoints are unchanged.
- Model checkpoint selection in C retained epoch0 for all fluid runs and the single-seed no-position-momentum ablation. This is an unfavorable result, not omitted or replaced with post-test tuning.
- Published PDF retrieval from research.aalto.fi returned403. An alternate retrieval attempt stalled in the tool layer and was interrupted by user status steering; no recovered PDF is claimed. The original retained text extraction remains available.
